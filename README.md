# TripSplitter

多人、多幣別旅程分帳工具，使用 Firebase Realtime Database 與 GitHub Pages。

## 使用

- 夥伴可停用及重新啟用；歷史帳目與結算不受影響。
- 公積金支付不列入個人代墊。TWD、JPY、KRW 以整數最小單位分攤，其餘支援幣別使用分；每筆尾差按成員 ID 固定順序分配。
- 「管理」提供 CSV、JSON 備份還原、異動紀錄及刪除復原。還原需確認，且會先下載還原前備份。
- 異動紀錄每頁最多 10 項，刪除復原每頁最多 5 項，依時間由新到舊排列。各紀錄可個別移除，會先要求確認；移除復原紀錄後無法從此處復原。清理操作不更動有效帳目與公積金，也不另外產生一筆異動紀錄。
- JSON 包含完整帳務紀錄與收據連結，不包含雲端照片原始檔。
- 異動紀錄署名由各裝置自行選擇，同時記錄 Firebase 匿名使用者 UID。署名不代表經驗證的個人身分。
- 公積金明細包含歷史期初、新入金、支出、退款對象、退款備註及餘額調整原因。舊版歷史期初由既有餘額及已記錄支出推算，無法回溯個別入金來源或過往調整。

## 資料相容與同步

舊版房間可直接讀取；首次帳務操作會以相容的陣列格式儲存 schemaVersion 2。**更新後請所有成員重新載入網頁再開始記帳**；舊分頁仍可能使用舊版整房覆寫程式。

新版每次帳務操作有獨立 UUID，透過 Firebase transaction 在最新版本上套用。不同帳目可並行更新；同一筆帳目以版本檢查攔截衝突。操作、異動紀錄與公積金餘額同一交易提交，重試不重複入帳。雲端寫入失敗會保留本機待同步操作，重新載入後可重試。

快取與待同步操作以房間分隔，每筆操作使用獨立 localStorage key，避免同瀏覽器分頁互相覆蓋。衝突時可下載待同步變更，再明確選擇採用雲端版本。備份還原檢查整個房間版本，避免覆蓋預覽後新產生的帳目。

此變更未修改 Firebase 安全規則或新增存取權限；異動紀錄是應用程式紀錄，不是防竄改稽核系統。

## 登入與旅程帳號權限（2026-10-23）

登入方式為 Firebase Email／密碼與 Google。Email 註冊需驗證；忘記密碼使用 Firebase 寄送重設信。應用程式不保存密碼，旅程管理員也不能查看密碼。Google 登入若同 Email 已有不同供應商，依 Firebase 的單一 Email 帳號連結設定處理。

既有未設權限的旅程，只能由驗證完成的 chrisaner@gmail.com 在第一次加入時接管，並將自己綁定 kris（若旅程有此記帳成員）。既有財務資料保持原樣。其他帳號由管理員以 Email 建立邀請，再將旅程連結交給對方；系統不另外寄出邀請信。註冊帳號不等於獲得旅程權限。

權限：擁有者可管理其他管理員；管理員可邀請及管理記帳／唯讀帳號；記帳成員可新增、編輯、刪除與復原支出，及公積金入金；唯讀成員可查看與匯出。記帳成員管理、公積金調整／退款、備份還原、異動紀錄與刪除復原紀錄清除需管理員。移除帳號資格不刪除歷史記帳成員與支出，不能移除自己或變更擁有者。

帳務及權限寫入統一經 roomApi callable，由雲端驗證 UID、驗證過的 Email、當下旅程資格及操作權限。財務異動與資格判斷使用同一個房間根交易，保留去重、版本衝突與備份 epoch 保護。異動署名由雲端決定；這仍不是不可竄改的法規稽核紀錄，管理員仍能清除紀錄或還原備份。

Realtime Database 預設禁止讀寫；只開放已驗證旅程成員讀取 state、本人讀取自己的資格及 OCR 工作。前端無法直接寫入帳目、OCR 工作或權限。Storage 前端規則拒絕所有存取；新照片由 roomApi 驗證資格後上傳，沒有建立公開下載 Token。過往已發出的 Cloud Storage Token 連結不會因修改規則自動失效，如有外流需要另行撤銷。

本機帳目快取與待同步操作使用帳號 UID 及旅程隔離。未登入不讀取帳目快取；登出清除快取與畫面。有待同步操作會阻擋主動登出，非預期登入失效則保留該帳號的待同步佇列。舊匿名版待同步資料不會自動歸屬給新帳號，原管理員可下載後人工核對。其他裝置請關閉舊分頁並重新整理。

測試：`node --test tests/*.test.*`。完整模擬器還須執行 `tests/security.rules.test.cjs` 與 `tests/accounts.integration.cjs`。本機瀏覽器測試使用 localhost 的 `?emulators=1`，此開關在正式網站網域無效。測試依賴工具位於 diagnostics/auth-tools，不屬於正式部署。

部署：先備份 Firebase 原資料與規則，部署 `functions`，確認 Email／密碼、Google 與 chrisaner.github.io 授權網域，再發布前端與 `database,storage` 規則。functions predeploy 會將共享財務邏輯複製到後端，避免前後端版本不一致。部署函式不會部署尚未啟用的 infra/billing-guard。正式啟用狀態須以雲端與網站驗證為準。
